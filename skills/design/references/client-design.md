# 客户端设计

基于已对齐的领域统一语言与接口契约完成图形客户端设计与实现闭环，通过 AI 自动化自验与用户最终验收锁定产品需求与多端交互基线。

## 执行流程

1. 底座对齐与更新（串行）：
   - 当处理存量变更时，读取既有 `DESIGN.md`、`context.md`、`ui/` 组件库与传输拦截桩，优先复用既有语义令牌与受控组件，仅按需增量补齐本次共用的新组件变体、协议请求、拦截桩与路由入口，避免破坏既有页面结构。
   - 当启动全新客户端应用时，先与用户确认目标平台家族集合（桌面与 Web、移动端、终端 TUI）与具象视觉参照物，确认后再初始化客户端包、运行宿主与客户端根目录（单包项目在仓库根目录）的 `DESIGN.md`；当关键页面布局存在分叉时，在同一路由挂载 2-3 个结构迥异的变体对比确认后清理。
   - 建立或增量更新亮暗对称的主题材质令牌、多端自适应 `ui/` 受控组件层、全状态展厅（Gallery）、静态守卫测试与导航壳层。
   - 依据阶段 2 契约摘要编写客户端协议请求层与 RFC 9457 错误解析代码，将手写契约类型隔离在独立占位模块（留待端到端联调时由后端 OpenAPI 自动生成覆盖），仅在底层网络传输或数据源层挂载确定性拦截桩（覆盖正常流、空态、加载态、慢请求竞态与业务错误），使后续连接真实后端时仅需替换生成类型并切换环境配置，无需重写页面调用代码。
2. 页面与状态交付（按目录作用域路由）：
   - 当本次变更涉及多个互不相交的独立页面目录时，将共享底座（`DESIGN.md`、`ui/`、导航壳层、协议层与拦截桩）冻结为只读，派发独立子代理在隔离 `Worktree` 中并行编写各页面与对应 `store` 纯函数单元测试（隔离机制同后端切片，不创建 GitHub 工单，且避免页面实现细节污染主对话上下文）。
   - 当仅涉及单页、同页修改或共享状态变更（写作用域相交）时，直接单线程完成。
3. 宿主自验（运行态全量排查）：
   - 合并页面代码后启动本地真实宿主，使用浏览器、桌面或终端自动化工具通过无障碍树逐页操作每一个交互点与状态，切换亮暗双主题与各目标平台视口。
   - 调用视觉能力审阅页面截图，排查修复控制台报错、对齐偏移、外置焦点环裁切与横向溢出，确保无交互与视觉缺陷后再交付用户验收。
4. 用户最终验收：
   - 交由用户在真实运行环境中实际操作并确认需求，根据反馈调整界面。
   - 当体验暴露出业务术语歧义或接口字段缺失时，回退至战略设计或契约设计修订。
5. 固化精简无头验收测试与主干合入：
   - 用户确认定稿后，按页面补齐或增量更新精简的无头交互验收测试（多页时同样派发独立子代理按页面目录并行），仅覆盖关键路径与边界态供本地与 CI 常态化防回归；后续无界面变更时不触发视觉验证。
   - 遵循 Trunk-Based Development，严禁直接推送 `main`，所有通过门禁的客户端改动必须从独立分支创建 PR 合入 `main`：
     - 当属于纯前端变更或尚无线上发布的全新项目时，直接激活入口并合入 `main`（纯前端项目或纯前端变更至此结束）。
     - 当属于存量前后端联动的新增页面或入口时，遵循 Keystone Interface 将新路由或入口标记为 `Planned`（仅开发与测试环境可达，生产构建屏蔽）后合入 `main`，确保主干随时可热修复且不暴露未联调页面。
     - 当属于存量前后端联动的既有页面变更时，遵循 Branch by Abstraction 将新版视图或模块作为独立实现合入 `main`（既有生产挂载点继续指向旧实现，避免在旧代码内散落条件开关），留待末尾整体验收切换并清理旧实现。
   - 当本阶段合入主干后仍需继续推进阶段 4 后端设计时，应当开启新会话直接基于最新 `main` 进入阶段 4，避免界面与截图上下文污染后端设计。

## 架构与测试细则

- 视觉与组件分层：严禁在业务页面直接编写硬编码色值、字号圆角或绕过共享 `ui/` 层自行编写控件，必须仅组合 `ui/` 受控组件与布局原语；缺少变体时先扩充 `ui/` 层再消费。
- 间距归属与静态守卫：内边距归组件自身、元素间距归父容器，避免双倍内边距；由静态守卫测试扫描拦截硬编码色值、内联样式覆盖，并校验亮暗主题键值对称。
- 状态与即时响应归属：领域状态归 `store`（仅暴露只读访问与语义变更方法），瞬态表单草稿归页面，虚拟长列表复用行状态按稳定领域 ID 外置存储；需主线程即时响应的禁用或关闭拦截约束预先声明为状态属性，避免阻塞等待异步回调。
- 无头交互验收测试边界：注入传输拦截桩、内存存储与手动时钟零等待快进；严禁绑定内部节点层级或导出私有状态供测试读取，必须仅使用无障碍角色、标签或可见文本语义选择器定位元素，覆盖主流程、空态/加载/错误/断网、慢请求竞态不覆盖新结果、返回栈状态保留、长列表滚动复用与多端视口切换。

## 产物模板

客户端根目录或仓库根目录 `DESIGN.md`：

```markdown
# <应用名称> 设计规范

<1-2 句话写明支持的目标平台家族集合（桌面与 Web / 移动端 / 终端 TUI）、核心用户任务与具象视觉参照物，不使用空泛形容词>

## 设计原则

- <3-4 条可检验的层级、密度与克制度准则，如依靠字阶、分割线与表面深度建立层级而非色块填充>

## 色彩与表面材质

- 令牌事实源：<指向代码中的主题令牌与表面材质文件路径；下文仅引用语义令牌名，不抄写具体色值或像素>
- 色阶与强调色：<页面底色、卡片、内凹区、凸起区的明暗递进关系，以及单一主强调色与状态色的允许作用范围>
- 表面材质：<卡片、内凹槽、凸起控件与浮层在亮暗主题下的顶光高光、边框、阴影与毛玻璃成对规则>

## 排版、空间与多端适配

- 字体与排版：<标题、正文、等宽辅助标签的层级职责及中西文标点与字距规则>
- 空间与对齐：<容器尺度、间距语义关系、内边距归组件与间距归父容器约束、同心圆角及共享对齐基线>
- 跨平台家族映射：<桌面指针紧凑密度与多栏常驻导航、移动端最小触控热区与导航栈/底部抽屉变形、终端整格字符对齐的适配规则>

## 共享控件目录

- <列出 `ui/` 层受控组件、语义变体（`variant` / `size`）及完备交互态（常规、悬停、按压、展开、焦点环、选中、禁用、加载、错误）与键盘无障碍契约；页面层仅负责布局摆放与选变体>

## 页面拓扑、命令与文案

- 壳层与页面地图：<全局导航壳层结构、各路由页面坐标与核心用户任务>
- 命令与文案规范：<主按钮、菜单、快捷键多入口同源规则，上下文经济文案原则及二次弹窗省略号 `…` 约定>

## 动效清单

- <前置列出页面与控件状态切换对应的动画方式、时长曲线令牌及 `prefers-reduced-motion` 降级行为>

## 推荐与禁止

- 推荐：<必须贯彻的标志性视觉与交互做法>
- 禁止：<明确禁止的低质视觉堆砌或反模式>
```
