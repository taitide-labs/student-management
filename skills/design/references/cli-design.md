# 命令行设计

遵循 clig.dev 规范，基于已对齐的领域统一语言与接口契约设计命令树并输出模拟终端交互，在编写实现代码前低成本确认命令行体验。

## 执行流程

1. 规划命令契约：
   - 当处理存量变更时，读取既有命令入口与 `context.md`，遵循 Parallel Change 保持既有子命令、参数与退出码兼容。
   - 当启动全新命令行应用时，遵循 clig.dev 规划正交的动作与对象子命令层次、参数类型、结构化输出格式（如 `--json`）及退出码语义。
2. 输出模拟终端示例：
   - 严禁提前编写实现代码、契约桩或测试，必须在对话中直接输出完整命令树，以及核心子命令的 `--help`、正常输出、非交互管道模式与典型报错（含 `stderr` 提示与退出码）模拟终端示例供确认。
3. 用户确认：
   - 依据用户反馈调整命令结构、选项命名与输出排版；当整理或确认中暴露出业务术语歧义或接口字段缺失时，回退至战略设计或契约设计修订。
   - 当命令行形态确认后，按需落盘关键选型 ADR，并在当前会话内直接进入下游冻结命令入口骨架与黑盒验收测试。
